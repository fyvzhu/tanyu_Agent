## 一、HTTP契约对齐（422错误修复）

### 问题
- 前端发送 `{text: "你好"}` 但后端要求 `{message: "..."}`
- 前端用 `res.code === 0` 判断成功，但后端返回 `{success, data}`
- 商品/订单点击只发送 `{object: ...}`，缺少 message 字段

### 修复
1. **ChatView.vue**:
   - `sendTextMessage`: 改为 `{message: text}`
   - `sendOrder/sendProduct`: 改为 `{message: "...", client_context: {...}}`
   - `sendPayload`: 响应处理改为 `response.data.text`

2. **后端**:
   - `chat_repository.py`: 修复 `get_first_user_message` 查询字段（`ChatMessage.text` → `ChatMessage.content`）

### 验收步骤

```bash
# 2. 启动前端（另一个终端）

```

## 二、前端会话状态统一（消息丢失修复）

### 问题
- `ChatView.vue` 和 `chat.js` 各维护一份 `messages`
- 切换会话时两者不同步，导致消息丢失
- 后端返回 `{role: "assistant", content: "..."}` 未映射成页面格式

### 修复（参考 chatgpt-web + yudao kefu）
1. **chat.js store**:
   - 引入 `sessionMessagesMap = Map<sessionId, messages[]>` 缓存
   - 添加 `transformHistoryMessage()` 映射字段（`assistant→bot`, `content→text`）
   - `switchSession()` 实现：缓存优先 + 防过时请求覆盖
   - 导出 `currentMessages` computed 作为唯一数据源

2. **ChatView.vue**:
   - 删除独立的 `messages = ref([])`
   - 改用 `messages = computed(() => chatStore.currentMessages)`
   - 删除 `fetchChatHistory()` 和 watch
   - `appendMessage()` 改为调用 `chatStore.addMessage()`

### 验收步骤
```javascript
// 浏览器控制台测试

input.value = "S1的消息"

// 2. 创建S2

// 3. 切回S1

// ✅ S1的消息应该显示，不应该为空

```

## 三、Redis异常处理收紧

### 问题
- `chat_router.py` 捕获 `aget_state()` 异常后使用空状态
- 将"Redis不可用"伪装成"新会话"，导致任务状态悄悄重置

### 修复（参考 langgraph-redis 官方实践）
```python
# 修改前
except Exception as e:
    logger.warning(f"checkpoint 恢复失败: {e}，使用空 state")
    restored_state = {...}  # 空状态

# 修改后
except Exception as e:
    logger.error(f"Redis checkpoint 读取失败: {e}")
    raise HTTPException(
        status_code=503,
        detail="会话状态服务暂时不可用，请稍后重试"
    )
```

### 验收步骤
```bash
# 1. 正常发送消息，观察日志
# ✅ 应该看到 "📦 从 checkpoint 恢复 persistent state"

# 2. 模拟Redis故障（停止Redis容器）
docker stop redis-container

# 3. 再次发送消息
# ✅ 应该返回 503 错误
# ✅ 日志应显示 "❌ Redis checkpoint 读取失败"
# ❌ 不应该显示 "🆕 首次对话，初始化 persistent state"

# 4. 恢复Redis
docker start redis-container

# 5. 再次发送消息
# ✅ 应该恢复正常，显示 checkpoint 恢复日志
```
