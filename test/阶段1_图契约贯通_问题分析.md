### 问题2: Guard状态值不一致（P0-7）

**当前状态**：
- Guard节点生产：`"passed"`, `"hallucination_detected"`
- 路由函数期望：`"pass"`, `"retry"`, `"fallback"`

**不一致点**：
- Guard设置 `"passed"` → 路由读取时默认为 `"pass"`（能工作但语义不统一）
- Guard设置 `"hallucination_detected"` → 路由无法识别，会默认为 `"pass"`（**严重错误！**）

**影响**：
- 检测到幻觉时，应该走fallback分支，但实际上会被当作pass返回给用户
- 这正是文档所说的"兜底文本已经在Guard节点被写入，所以路由仍可能结束并返回兜底文本；但这并不表示Guard通过"

**修复方案**：
```python
# hallucination_guard.py
if hallucination_detected:
    state["guard_status"] = "fallback"  # 改为 fallback
else:
    state["guard_status"] = "pass"      # 改为 pass
```

### 问题3: TurnAction应该是枚举而非字符串

**当前状态**：
- `turn_action: str | None`
- 使用魔法字符串 `"accept"`, `"clarify"` 等

**问题**：
- 容易拼写错误
- IDE无法自动补全
- 没有类型检查

**修复方案**：
```python
# state.py 或 models.py
class TurnAction(str, Enum):
    ACCEPT = "accept"
    CLARIFY = "clarify"
    SELECT_INTENT = "select_intent"
    CHITCHAT = "chitchat"
    CANCEL = "cancel"
    RESUME_NOTICE = "resume_notice"
    UNSUPPORTED = "unsupported"
    CLASSIFIER_FAILURE = "classifier_failure"
    OUT_OF_SCOPE = "out_of_scope"
```

---

### 问题4: 路由函数缺少穷尽检查

**当前状态**：
- `route_after_intent` 有兜底 `return "respond"`
- `route_after_guard` 也有兜底 `return "pass"`

**问题**：
- 未知的 `turn_action` 会被静默处理
- 未知的 `guard_status` 会被当作通过

**修复方案**：
```python
def route_after_intent(state: AgentState) -> Literal["respond", "check_slots"]:
    turn_action = state.get("turn_action")
    
    # 穷尽检查
    if turn_action == "accept":
        return "check_slots"
    elif turn_action in {"cancel", "chitchat", "clarify", "select_intent", "resume_notice"}:
        return "respond"
    else:
        # 未知状态 - 抛出错误或记录严重警告
        logger.error(f"未知的 turn_action: {turn_action}")
        raise ValueError(f"Unknown turn_action: {turn_action}")
```
