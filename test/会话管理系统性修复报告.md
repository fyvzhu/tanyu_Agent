## 📋 执行摘要

按照用户提供的详细诊断，完成了客服系统聊天会话的三大核心修复，参考了官方 langgraph-redis、chatgpt-web 和 yudao-kefu 的最佳实践。

## 🔍 问题诊断回顾

### 直接原因

1. **发送"你好"报422**
   - 前端：`{text: "你好"}` 
   - 后端要求：`{message: "..."}`
   - FastAPI在Schema验证阶段直接拒绝

2. **切回第一会话后内容消失**
   - ChatView.vue 维护独立 `messages = ref([])`
   - chat.js store 也维护 `messages = ref([])`
   - 切换时 store 异步加载但页面先清空

3. **Redis故障伪装成新会话**
   - `aget_state()` 异常被捕获后使用空状态
   - 无法区分"首次对话"和"Redis不可用"

### 修复2：会话状态统一

**文件**: `customer-service-frontend/src/stores/chat.js`

核心改动：
1. 引入 `sessionMessagesMap = Map<sessionId, messages[]>`
2. 添加 `transformHistoryMessage()` 字段映射
3. `switchSession()` 实现缓存优先+防过时
4. 导出 `currentMessages` computed

```javascript
// 转换后端格式 → 页面格式
function transformHistoryMessage(backendMsg) {
  return {
    role: backendMsg.role === 'assistant' ? 'bot' : backendMsg.role,
    text: backendMsg.content || '',  // content → text
    message_id: backendMsg.message_id,
    turn_id: backendMsg.turn_id,
    objects: backendMsg.objects || [],
  }
}

// 防过时请求覆盖
const requestId = ++lastSwitchRequestId
// ... 异步加载 ...
if (requestId !== lastSwitchRequestId) {
  console.log('请求已过时，忽略')
  return
}
```

**文件**: `customer-service-frontend/src/views/ChatView.vue`

```javascript
// 修改前
const messages = ref([])

// 修改后
const messages = computed(() => chatStore.currentMessages)
```

删除冗余：
- ❌ `fetchChatHistory()`
- ❌ `setHistoryMessages()`
- ❌ `watch(() => chatStore.currentSessionId, ...)`

### 修复3：Redis异常处理

**文件**: `customer-service-backend/customer_service/api/router/chat_router.py`

```python
# 修改前
except Exception as e:
    logger.warning(f"checkpoint 恢复失败: {e}，使用空 state")
    restored_state = {...}  # 伪装成新会话

# 修改后
except Exception as e:
    logger.error(
        f"Redis checkpoint 读取失败: {e}，"
        f"为避免任务状态丢失，终止本轮处理"
    )
    raise HTTPException(
        status_code=503,
        detail="会话状态服务暂时不可用，请稍后重试"
    )
```

## 🎯 设计原则

1. **单一数据源**：Store是唯一的消息权威来源
2. **防御式编程**：过时请求、异常故障明确处理
3. **契约优先**：前后端字段严格对齐
4. **故障可见**：Redis异常返回503，不伪装
