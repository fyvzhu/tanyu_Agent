# 阶段1重新设计方案 - 基于参考代码学习

## 📚 参考代码学习总结

### 参考代码1：ecommerce-customer-service（核心架构）

#### 关键设计模式：提议→验证→执行

**1. TurnPlan（提议层）**
- 模型输出三条轨道：`task`、`knowledge`、`chitchat`
- `task` 轨道包含命令列表：`StartFlowCommand`、`SetSlotsCommand`、`ResumeFlowCommand`、`CancelFlowCommand`
- 模型不决定"执行哪个节点"，只提出"想做什么"

**2. TurnPlanValidator（验证层）**
```python
def validate(self, state: DialogueState, turn_plan: TurnPlan) -> TurnPlanValidationResult:
    # 检查1：多轨道冲突
    if 多条轨道同时存在:
        return reject(MULTIPLE_TRACKS)
    
    # 检查2：命令白名单
    if command not in [StartFlow, SetSlots, Resume, Cancel]:
        return reject(INVALID_COMMAND)
    
    # 检查3：多Flow冲突
    if len(start_commands) > 1:
        return reject(MULTIPLE_TASK_FLOWS)
    
    # 检查4：Flow注册检查
    if flow not in registry:
        return reject(FLOW_NOT_FOUND)
```

**3. CommandProcessor（执行层）**
- 按顺序执行验证通过的命令
- 处理任务栈：`start`、`interrupt`、`resume`、`cancel`
- 生成系统上下文：`StartedSystemContext`、`InterruptedSystemContext`

#### DialogueState 结构
```python
@dataclass
class DialogueState:
    active_task: TaskContext | None
    paused_tasks: list[TaskContext]  # 暂停栈
    active_system_task: SystemContext | None
    focused_object: FocusedObject | None
```

## 🔍 当前项目代码与参考代码的对比

### 当前架构的问题

| 层次 | 当前实现 | 参考代码 | 问题 |
|------|---------|---------|------|
| **分类** | intent_parse 直接设置 turn_action | 模型输出 TurnPlan | 没有提议→验证分离 |
| **验证** | 无独立验证层 | TurnPlanValidator | 多目标、命令白名单无检查 |
| **执行** | 直接路由到节点 | CommandProcessor | 任务栈管理分散 |

### 具体缺失

1. **P0-1：turn_action 生产者问题**
   - ❌ 当前：分类器直接设置字符串
   - ✅ 应该：分类器提出候选，验证器决定接受/拒绝

2. **P0-3：多目标处理**
   - ❌ 当前：pending_intent_selection 只存候选，选择后实体丢失
   - ✅ 应该：TurnPlan 包含完整的目标+实体，验证器检测冲突

3. **P0-5：任务完成不调用complete**
   - ❌ 当前：response_gen 手动写 task_transition
   - ✅ 应该：CommandProcessor 统一管理栈操作

4. **P0-6：闲聊创建持久Task**
   - ❌ 当前：chitchat 走 start_or_continue_task
   - ✅ 应该：闲聊不进入 task 轨道

## 🎯 重新设计方案

### 核心原则
> "模型提议下一步，对话规则决定本轮实际推进什么"

### 新架构（三层分离）

```
用户消息
   ↓
[分类器] → IntentClassificationResult
   ↓         (recognized, intent, entities, confidence)
[验证器] → TurnDecision
   ↓         (action: ACCEPT/CLARIFY/..., reason, allowed_commands)
[执行器] → 按 action 路由到节点
```

### 关键数据结构

#### 1. IntentClassificationResult（分类器输出）
```python
@dataclass
class IntentClassificationResult:
    """分类器的原始输出，不做决策"""
    goals: list[IntentGoal]  # 可能多个目标
    confidence: float
    raw_response: dict  # LLM原始输出

@dataclass
class IntentGoal:
    intent: BusinessIntent
    entities: dict[str, Any]
    text_span: str  # 对应的原句片段
```

#### 2. TurnDecision（验证器输出）
```python
@dataclass
class TurnDecision:
    action: TurnAction  # ACCEPT/CLARIFY/SELECT_INTENT/...
    reason: str | None
    accepted_goal: IntentGoal | None  # 接受的目标
    clarify_options: list[IntentGoal] | None  # 多目标澄清选项
```

#### 3. 命令白名单（参考代码1）
```python
ALLOWED_COMMANDS = {
    "start_flow",
    "set_slots",
    "resume_flow", 
    "cancel_flow"
}
```
