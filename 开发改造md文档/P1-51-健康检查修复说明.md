# P1-51: Agent Readiness 健康检查修复

## 问题描述

Agent 8000 的 `/health/ready` 端点存在以下问题：
1. LLM 标记为 `not_checked`，未实际验证
2. Commerce API 只检查 `/health/live`，未尝试 `/health/ready`
3. 缺少对 Qdrant、Elasticsearch、Embedding 服务的检查
4. 未区分关键依赖和可选依赖，无法正确报告降级状态

## 修复方案

### 依赖分类

**关键依赖**（任一失败返回 503 unavailable）：
- Agent Graph
- Database
- Redis
- Commerce API
- LLM

**可选依赖**（失败降级为 degraded，但仍返回 200）：
- Embedding 服务
- Qdrant
- Elasticsearch

### 健康状态定义

1. **ok**: 所有关键依赖可用，可选依赖全部可用
2. **degraded**: 关键依赖可用，但部分可选依赖不可用（HTTP 200）
3. **unavailable**: 至少一个关键依赖不可用（HTTP 503）

### 实现细节

#### 1. Agent Graph 检查
```python
from customer_service.graph.graph_manager import get_agent_graph
get_agent_graph()  # 验证 graph 已初始化
```

#### 2. Database 检查
```python
async with async_session() as session:
    await session.execute(text("SELECT 1"))
```

#### 3. Redis 检查
```python
redis = get_redis()
await redis.ping()
```

#### 4. Commerce API 检查
```python
# 优先尝试 /health/ready，失败则回退到 /health/live
try:
    response = await client.http.get(f"{client.base_url}/health/ready", timeout=2.0)
except httpx.HTTPStatusError:
    response = await client.http.get(f"{client.base_url}/health/live", timeout=2.0)
```

#### 5. LLM 检查
```python
llm = get_llm()
await llm.ainvoke("test")  # 简单的生成测试
```

#### 6. Embedding 检查（可选）
```python
if settings.embedding_enabled:
    embedding = get_embedding_service()
    await embedding.embed("test")
```

#### 7. Qdrant 检查（可选）
```python
if settings.qdrant_enabled:
    qdrant = AsyncQdrantClient(url=settings.qdrant_url, timeout=2.0)
    collections = await qdrant.get_collections()
    await qdrant.close()
```

#### 8. Elasticsearch 检查（可选）
```python
if settings.elasticsearch_enabled:
    es = AsyncElasticsearch([settings.elasticsearch_url], request_timeout=2.0)
    health = await es.cluster.health()
    await es.close()
```

### 响应格式

```json
{
  "status": "ok|degraded|unavailable",
  "dependencies": {
    "agent_graph": "ok",
    "database": "ok",
    "redis": "ok",
    "commerce": "ok",
    "llm": "ok",
    "embedding": "ok|degraded|disabled",
    "qdrant": "ok|degraded|disabled",
    "elasticsearch": "ok|degraded|disabled"
  },
  "critical_failures": ["service_name"],  // null if none
  "optional_failures": ["service_name"]   // null if none
}
```

## 验证步骤

1. 启动所有基础设施服务（MySQL、Redis、Qdrant、ES）
2. 启动 Commerce API (8001)
3. 启动 Agent (8000)
4. 测试健康检查：
   ```bash
   # 所有服务正常
   curl http://localhost:8000/health/ready
   # 应返回 200，status: "ok"
   
   # 停止 Qdrant
   # 应返回 200，status: "degraded"，optional_failures: ["qdrant"]
   
   # 停止 Commerce API
   # 应返回 503，status: "unavailable"，critical_failures: ["commerce"]
   ```

## 注意事项

1. 健康检查端点不需要认证（无需 JWT）
2. 使用短超时（2 秒）避免阻塞
3. 错误信息截断至 100 字符，避免响应过大
4. 可选依赖失败不影响服务可用性，只标记为降级
5. LLM 检查改为关键依赖，因为 Agent 核心功能依赖 LLM
