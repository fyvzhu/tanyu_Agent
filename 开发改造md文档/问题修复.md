三十七、离线索引脚本的全量入口调用参数错误【P0】。 build_product_index.py 第 58–62 行 用 search_products(page=1, page_size=1000) 调用客户端，但 EcommerceClient.search_products() 只接收一个 params 字典。执行 --all 会先遇到参数错误。即便修正调用，它也只取第一页，仍不能满足 v7 要求的完整分页枚举。应统一调用签名，并迭代至最后一页；同时补齐文档规定的 --full、--product-id、--batch-size 和安全的 --delete-missing 语义。

三十八、离线批量向量化与仓库自带 Embedding 服务的请求、响应格式不一致【P0】。 EmbeddingClient.embed_batch() 发送 {"inputs": [...]} 并预期直接得到数组；docker/embedding/embedding_service.py 接收的是 {"text": [...]}，返回的是含 embeddings 的对象。修好第三十七点后，这里仍会失败或进入本地模型回退。应冻结一种 Embedding HTTP 契约，让离线写入与在线查询都按同一模型和维度执行。

三十九、索引 Manifest 的异步函数未被 await【P0】。 ProductIndexBuilder 把异步 should_reindex() 返回的协程当布尔值；成功和失败分支调用 update_manifest() 也都没有 await。因此增量判断不会真正查询数据库，构建状态也不会可靠写入。两处都应等待执行，并验证首次构建、跳过未变化商品、变更后重建和失败记录。

四十、离线写入与在线查询使用了不同的索引名称和客户端实现【P0】。 索引脚本实例化的 旧 Qdrant 客户端 和 旧 ES 客户端 写入 product_chunks；应用启动构造的在线检索实例 默认查询 product_knowledge。这正是“索引脚本显示成功，但聊天检索不到新数据”的可能根因。应让 Builder 和在线检索共用配置及目标集合，并删除不再使用的重复客户端。

四十一、Qdrant Point ID 使用了不支持的字符串格式【P0】。 Chunker 产生类似 15970:overview:0 的逻辑 chunk_id，写入代码 直接把它用作 Point ID。Qdrant 的 Point ID 要求无符号整数或 UUID。 可保留现有逻辑 chunk_id 在 payload 中，并从它稳定生成 UUID 作为 Point ID。

四十二、ES 写入字段与在线查询字段不一致【P0】。 离线写入 把卖点、材质等切分内容放在 text；在线 ES 查询 却搜索 product_display_name、material、selling_points 等字段，没有搜索 text。用当前 Builder 建出的索引，内容关键词无法按预期命中。应以实际索引映射冻结查询字段，并用一条“只出现在卖点正文中的词”验证召回。
